# توثيق وقرارات نظام التصميم — ملف المدرب وتوصيف المقرر

هذا المستند يوثّق كافة القرارات المعمارية والبصرية وحالات الواجهة لنماذج التصميم الساكنة لشاشات النظام الثلاث في مجلد `design/`، لتمكين مطوّر الـ React من فهم فلسفة الواجهة وتحويلها إلى مكونات برمجية متطابقة بدقة.

---

## ١. القرارات التصميمية المعمارية والبصرية

### أ) اللغة البصرية والهوية (Visual Language)
1. **الاستقلالية التامة عن الإنترنت (Standalone & Zero CDN):**
   - تم الاعتماد كلياً على مكدس خطوط النظام الحديثة (`IBM Plex Sans Arabic`, `Segoe UI`, `Tahoma`, `system-ui`) لواجهات الاستخدام، مع الحفاظ على خط الوثيقة المعتمد (`Sakkal Majalla`) للوثائق المطبوعة.
   - كافة الأيقونات مرسومة كـ inline SVGs بأسلوب أيقونات **Lucide** (سُمك ۲ بكسل، نهايات مستديرة) دون تحميل أي مكتبة خارجية.
2. **اللوحات المعنونة (Titled Panels):**
   - كل جدول، نموذج، أو قائمة مغلفة داخل عنصر `.ui-panel` يبتدئ بشريط عنوان ممتلئ داكن (`--ui-bar: #4a4a4a`) بنص أبيض ناصع وأيقونة مميزة، وفي الطرف المقابل عدّاد سياقي مميز (`.counter`) بلون التركواز المعتمد (`--ui-accent: #2aa39a`).
3. **أدوات التصفية والتبويبات (Filter Chips):**
   - التزاماً بالقاعدة الصارمة للمالك: الحالة النشطة (`.chip.active` أو `.seg button.on`) تظهر **بلون ممتلئ كامل ونص أبيض غامق** وليست بحالة باهتة أو شفافة.
4. **فلسفة الحفظ التلقائي (Auto-Save Experience):**
   - تم استبعاد أزرار الحفظ التقليدية لصالح الحفظ اللحظي المباشر، مدعوماً بمؤشر بصري دائم يتدرج بين حالتين:
     - `يحفظ...` (برتقالي / كهرماني مع دوران متحرك).
     - `حُفظ تلقائياً (توقيت)` (تركوازي داكن مع أيقونة التحقق).
5. **أولوية الطباعة المتقنة (`@media print`):**
   - تلغي قواعد الطباعة كافة الارتفاعات الثابتة وتفك الحاويات الممررة (`overflow: visible !important`)، وتخفي القشرة العلوية والأزرار التفاعلية ومربعات الحوار، لتنتج وثيقة ورقية أو ملف PDF جاهزاً للاعتماد الرسمي.

## ٢. تفصيل الشاشات والقرارات المنفذة

### ١) صفحة الأدمن (`admin.html`)
- **منطقة إفلات تقرير رايات (SS01 CSV Dropzone):**
  - مساحة إفلات مرئية مدعومة بزر استعراض صريح، توضح طبيعة التقرير المطلوب وحقوله المعتمدة.
- **بطاقة تلخيص الفصل المكتشف (Parsed Metrics):**
  - تُبرز مباشرة رقم الفصل المستخرج (مثل `144720`)، عدد الشعب، عدد المدربين، والأقسام بعد قراءة الملف.
- **جدول الفروق الدلالي (Semantic Diff Table):**
  - يُفرّق بصرياً ولونياً بين خمس حالات دقيقة:
    1. `+ شعبة جديدة` (خلفية خضراء ناعمة + شارة نجاح).
    2. `✓ إسناد مدرب` (خلفية زرقاء ناعمة + شارة إسناد).
    3. `⇄ تغيير مدرب` (خلفية كهرمانية + شارة تحذيرية).
    4. `✕ شعبة محذوفة / ملغاة` (خلفية حمراء ناعمة + شارة إلغاء مع خط شطب على البيانات السابقة).
    5. `= مطابقة دون تغيير` (خلفية بيضاء عادية).
  - مدعوم بشريط أزرار تصفية نشطة ممتلئة للتركيز على فئة فروق محددة.
- **أرشيف الفصول التدريبية السابقة:**
  - يتيح الرجوع إلى بيانات الفصول المؤرشفة والتبديل بين الفصل النشط والأرشيف.
- **استقبال ودمج نسخ المدربين الاحتياطية:**
  - قسم مستقل يسمح برفع وتجميع ملفات JSON المرسلة من المدربين، وعرض حالة الدمج لكل مدرب (`مدمج بنجاح`، `جاهز للدمج`، `تضارب إصدارات`).
- **زر إنتاج حزمة البيانات (Generate Data Package):**
  - عنصر ختامي مركزي بارز ومميز لإنتاج ملف الأرشيف الكامل، مشروح بسطر مباشر تحته يوضح أن الحزمة تُسلّم للمسؤول عن نشرها.

### ٢) صفحة دخول المدرب (`trainer-login.html`)
- **بساطة وطمأنينة متناهية (حقلان فقط):**
  - الحقل الأول: **رقم المدرب الوظيفي** (مع معالجة ذكية للأصفار البادئة مثل `13270 = 0013270` وتلميح توضيحي مريح).
  - الحقل الثاني: **الرقم المرجعي (CRN)** لإحدى شعبه.
- **الدليل البصري المصغر للجدول (Mini Schedule Guide):**
  - جدول مصغر يحاكي جدول رايات الفعلي، ويبرز خانة "الرقم المرجعي" بإطار مميز وشارة إرشادية خضراء («هذا هو الرقم المرجعي») لإزالة أي التباس لدى المدرب.
- **رسائل خطأ عربية دقيقة ومستقلة:**
  - حالة: *رقم المدرب غير مسجل في الفصل الحالي.*
  - حالة: *الرقم المرجعي لا يطابق أي شعبة مسندة لهذا المدرب.*
- **شريط أدوات تجربة الحالات (Demo Bar):**
  - أزرار سريعة أسفل البطاقة تتيح للمراجع والمطور اختبار حالة النجاح وحالتي الخطأ بنقرة زر واحدة.

### ٣) لوحة المدرب (`trainer-home.html`)
- **شريط «معلومات ناقصة» أعلى الصفحة:**
  - شريط لافت ذو تدرج كهرماني هادئ وإطار برتقالي يعد النواقص بدقة، ويحوي زر قفز فوري «إكمال البيانات الآن ←».
  - يختفي تلقائياً بمجرد اكتمال البيانات (وتم تضمين زر تبديل لمعاينة الواجهة قبل وبعد الاكتمال).
- **الرسالة الصريحة الدائمة:**
  - مصاغة بوضوح مطمئن في صندوق تنبيه تركوازي: *«تعديلاتك تُحفظ على جهازك فقط؛ ولحفظها بشكل دائم احفظ نسخة احتياطية وأرسلها لرئيس القسم.»*
- **بطاقات المقررات وشريط تقدم الاكتمال:**
  - كل بطاقة تعرض الرمز، الاسم، الشعب وأرقامها المرجعية، وشريط تقدم ملون بحسب نسبة الاكتمال.
- **حالة المقرر الذي لا خطة له بعد (Unplanned State Card):**
  - صُممت كبطاقة ذات إطار متقطع وشارة تنبيه حمراء ورسالة إرشادية واضحة تشرح أن المقرر مسند في رايات لكنه يحتاج إنشاء توصيف تفصيلي أو طلبه من رئيس القسم، مع أزرار إجراء مباشرة.
- **منبثقة إكمال البيانات الناقصة (Missing Data Modal):**
  - منبثقة تفاعلية مجمعة تقسم النواقص إلى خطوات سريعة (بيانات التواصل، الساعات المكتبية، مصادر التعلم).
  - مزودة بشريط تنقل مرقم ومؤشر حفظ تلقائي ينبض أثناء الكتابة لتأكيد الحفظ الفوري دون الحاجة لأي زر حفظ يدوي.

## ٣. قاموس الحالات والتسميات (States & CSS Classes Dictionary)

| :--- | :--- | :--- |
| **جاري الحفظ** | `.save-state.saving` | لون كهرماني + أيقونة دوران «يحفظ التغييرات...» |
| **تم الحفظ بنجاح** | `.save-state.saved` | لون تركوازي داكن + أيقونة صح «حُفظ تلقائياً» |
| **خطأ في الحفظ** | `.save-state.error` | لون أحمر داكن لتنبيه المستخدم بتعذر الحفظ المحلي |
| **شعبة جديدة** | `.diff-row.diff-add` | صف بخلفية خضراء ناعمة وشارة `+ شعبة جديدة` |
| **إسناد مدرب** | `.diff-row.diff-assign` | صف بخلفية زرقاء ناعمة وشارة `✓ إسناد مدرب` |
| **تغيير مدرب** | `.diff-row.diff-change` | صف بخلفية كهرمانية وشارة `⇄ تغيير مدرب` |
| **شعبة ملغاة** | `.diff-row.diff-del` | صف بخلفية وردية/حمراء وشارة `✕ شعبة محذوفة` |

| **مقرر بلا خطة** | `.course-card.unplanned` | إطار رمادي متقطع + إشعار كهرماني إرشادي |
| **مقرر مكتمل** | `.badge.complete` | شارة خضراء بنسبة 100% |
| **مسودة محلية** | `.badge.draft` | شارة كهرمانية ذهبية |
| **جاهز للدمج** | `.badge.info` | شارة زرقاء لنسخ المدربين الاحتياطية الصالحة |

## ٤. مسائل تركت لمرونة التطبيق (Open Design & Logic Decisions)

1. **آلية حل تضارب النسخ الاحتياطية (Merge Conflict Resolution):**
   - التصميم يوفّر زر `حل التضارب` في صفحة الأدمن؛ في تطبيق React الفعلي، يُقترح فتح حوار مقارنة حقل-بحقل (Field-by-Field Diff) يتيح للأدمن اختيار اعتماد تعديل المدرب أو الإبقاء على نسخة الخادم.
2. **صيغة حزمة البيانات المجمعة:**
   - زُوّد الزر بمحاكاة تنزيل ملف مضغوط `.zip`؛ يمكن في منطق React جعله ملف JSON موحد أو ZIP يحتوي على مجلدات كل تخصص ومقرراته.
3. **التجاوب مع الجوال (Mobile Responsiveness):**
   - تم تصميم الشاشات لتتكيف بسلاسة مع الشاشات الصغيرة (انهيار شبكات الأعمدة إلى عمود واحد، وتمرير الجداول أفقياً عبر `.table-responsive`).

## ٥. إرشادات التطبيق لمطوّر الواجهة (React Developer Hand-off)

1. **التعامل مع الأصفار البادئة (Leading Zeros):**
   - عند مطابقة رقم المدرب في نموذج الدخول، استخدم دالة التنظيف:
     ```typescript
     const normalizeId = (id: string) => id.trim().replace(/^0+/, '');
     ```
2. **المنبثقات (Modals) والحفظ التلقائي:**
   - اربط حقول النموذج بـ `debounce` (مثلاً 400ms) على دوال الحفظ في `localStorage` أو `IndexedDB`، وحدّث حالة المكون إلى `saving` ثم `saved`.
3. **فصل استدعاءات الطباعة:**
   - تم تجهيز `.no-print` على كافة العناصر غير التوثيقية، بحيث تكفي مناداة `window.print()` لطباعة الخطط بتنسيق متقن.
