# دروس مستفادة — مشروع ملف المدرب وتوصيف المقرر

## اختبار المتصفح (Playwright + HashRouter)
- **تنقّل الهاش لا يعيد تحميل الصفحة**: `pg.goto('#/course/X')` من صفحة بنفس
  الأصل هو hashchange داخل نفس الوثيقة — حالة React (مثل وضع التحرير) تبقى.
  للتحقق من ثبات البيانات بعد إقلاع جديد استخدم `pg.reload()` صراحةً.
- **innerText لا يشمل قيم حقول الإدخال**: فحص نصٍّ داخل `input`/`textarea`
  عبر `inner_text` يفشل صامتاً. افحص عبر `input_value()` أو اقرأ IndexedDB
  مباشرة، أو تأكد أولاً أن الصفحة في وضع العرض لا التحرير.
- ظهر كلا الخطأين معاً في تحقق مرحلة توسيع التحرير (٢٠٢٦-٠٧-٢٩) وأوهما
  بوجود ثلاث مشاكل غير حقيقية (تجهيزات «مفقودة»، حفظ «فاشل»، طباعة ٧ صفحات).

## نقل الأنماط من نموذج مرجعي
- عند نقل CSS من ملف مرجعي إلى المشروع تُنقل **متغيّرات :root معه** —
  `var(--x)` غير المعرّف لا يفشل بل يسقط للقيمة الأولية صامتاً (خلفية
  شفافة + نص أبيض = عنصر غير مرئي، كما حدث لـ«روابط مهمة»).
  الحارس: اختبار يجمع كل `var(--x)` المستعملة ويطابقها مع المعرّفة
  (print.test.ts: «كل متغيّر CSS مستعمَل معرّفٌ فعلاً»).
- **أصناف CSS عامة تتسرّب بين الشاشات**: كل ملفات CSS في التطبيق تُحمَّل
  معاً (App يستورد `CourseView` فيُحمَّل `render/document.css` في كل
  شاشة). فاسمٌ عام مثل `.block` أو `.sign` — وكلاهما `display:flex`
  هناك — يقلب تخطيط أي شاشة جديدة تستعمل الاسم نفسه، والقاعدة الأخصّ
  لا تنقذ إلا الخصائص التي تعلنها هي. حدث في صفحة الأدمن (٢٠٢٦-٠٨-٢٠):
  عنوانٌ وفقرةٌ وجدولٌ اصطفّوا في سطر واحد. القاعدة: أصناف الشاشة الجديدة
  تُسبق باسمها (`admin-block`)، وقواعدها كلها تحت صنف جذر الشاشة
  (`.admin-page …`) كي لا تتسرّب هي أيضاً إلى غيرها.

## الأرقام اللاتينية وسط نص عربي (bidi)
- رمز مثل «4 ـ 1» (أرقام لاتينية حول فاصل عربي) تعكس خوارزمية اتجاه
  النص ترتيبه المرئي في المتصفح فيُقرأ معكوساً. الحل الحتمي: أرقام
  هندية «٤ ـ ١» تتبع اتجاه السطر (دالة unitCode في vocab.ts) —
  لا حيل CSS (bidi-override يكسر الأرقام متعددة الخانات).

## استيراد سكربتات الاستخراج
- سكربتات الاستخراج تنتهي بـ`main()` مكشوفة؛ استيراد أحدها لإعادة استعمال
  محلّلاته **يشغّل main فيعيد كتابة ملفات البيانات المنقّحة** ويمحو
  التنقيح اليدوي (حدث لـplan-courses.json وplan-detail.json ٢٠٢٦-٠٨-٠٢).
  كل سكربت يُشغَّل تحت `if __name__ == "__main__":`.

## بيانات مستخرجة من PDF
- المستخرَج آلياً من جداول PDF يحمل شظايا صامتة: ترويسات تتسرب كبنود
  («الموضوع»)، كلمات مشطورة، أقواس معكوسة. أي بيانات تظهر في وثيقة
  مطبوعة تُراجع تحريرياً بنداً بنداً قبل اعتمادها، ويُضاف اختبار حارس
  على الأنماط المعروفة (planDetail.test.ts، واختبار «لا شظايا» في
  generator.test.ts).

## حالة الواجهة عبر مسارات المعامل (route params)
- مكوّن مسارٍ ذي معامل (`course/:id`) لا يُعاد إنشاؤه عند تغيّر المعامل —
  أي حالة (تحرير، مؤشر حفظ) تورَّث للمقرر التالي ما لم تُصفَّر في
  `useEffect` المرتبط بالمعرّف.

## الطباعة
- الحد المطبوع لـ A4 بهامش 8mm ≈ ١٠٦٢ بكسل؛ الصفحات المحسوبة ١٠٥٠+ على
  الشاشة تنشطر في PDF. عند إضافة محتوى نصي طويل (سلامة/تجهيزات) تُقاس
  ارتفاعات `.page` تحت `emulate_media('print')` وتُضبط الحشوات في
  `@media print` فقط — لا تُمسّ أنماط الشاشة.
- الطباعة أثناء وضع التحرير تُضخّم الصفحات (textareas) — زر الطباعة يجب
  أن يُنهي التحرير أولاً.
